# Pacemate testing report — 7 November 2026

## Scope and evidence

The current implementation uses Vue 3, Vue Router and Vite for the frontend; Supabase Auth, PostgreSQL, Storage, private Realtime and a bundled TypeScript Edge Function for the backend. Drizzle and postgres provide database access. Optional integrations are Resend, browser Web Push and Stripe. Frontend code lives in `src`, public install/offline assets in `public`, backend handlers in `supabase/functions/pacemate`, SQL in `supabase/migrations`, and automated checks in `tests`.

Validation: **64 automated tests pass; production frontend/backend build passes.** Tests simulate authentication, database responses, providers and browser transports. They do not prove that production SQL executes, policies work against real accounts, or external services deliver successfully. The user confirmed the earlier deployed database/stats flow works. The community release has not been deployed or its migration applied here. No browser visual, keyboard or mobile acceptance pass was available.

Severity: Critical = unauthorized access/payment or data loss; High = core workflow or safety failure; Medium = degraded workflow; Low = presentation. “Gate” identifies incomplete activation or verification, not a reproduced defect.

## Automatic versus manual testing

Automated coverage is appropriate for route matching, authentication rejection, role/membership checks, payload limits, provider signature verification, export filtering, save ordering, queue retry logic and service-worker caching rules. Existing checks cover these using mocks; a real PostgreSQL integration suite should additionally execute migration, RLS and concurrency cases.

Manual browser/device testing remains necessary for layout, focus trapping, keyboard navigation, camera/photo selection, install prompts, permissions, real delivery, OAuth/email recovery links and two-member interactions. Search-console ownership, provider credentials, scheduler activation and payment acceptance require configured external services.

Do not treat a successful build or mocked tests as launch approval. Follow `COMMUNITY_SETUP.md` in order, then complete the live acceptance checklist there before opening registration widely.
